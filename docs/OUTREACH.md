# Проработка ЖК

Раздел `/outreach` предназначен для самостоятельной первичной проработки выбранных объектов. Входящие лиды, мероприятия и активные клиенты не включаются в его статистику. Основные Google Sheets остаются read-only.

## Источник

Книга «Парсер ЖК», лист `expocrimea`, gid `782042761`. Исходный срез от 26.10.2026 содержит 47 строк. Два названия «Мойнако» с одинаковыми ID корпусов объединяются в одну карточку с сохранением обоих названий. Три неполные строки сохраняются для ручной проработки. Итого 46 объектов, первоначальный источник обращения — «Проверить источник».

Кнопка «Из таблицы» выполняет только GET CSV export. Обновляются характеристики ЖК, а не контакты, ответственный, этап или история. Отсутствие объекта в новой выгрузке не удаляет его. Удаление из рабочего списка — архивирование с восстановлением; синхронизация архив не снимает. Для неполного объекта при появлении ID корпусов сохраняется прежняя карточка по названию.

## Работа

Карточка хранит ответственного, источник, этап, состояние (в работе / отложено / отказ), основной и дополнительный контакты, следующее действие и срок. Для менеджеров используются текущие имена команды и Николай Герасимов из согласованного HTML.

Этапы: изучение ЖК, поиск ЛПР, закупка контактов, звонок, подарок и буклет, визит, встреча назначена, встреча проведена, КП отправлено. Описания и условия доступны по наведению и по нажатию на значок информации. Условия QR-сканирований и открытий КП являются памяткой; внешняя аналитика этих событий пока не подключена.

События назначения, проведения и отправки КП записываются отдельно, с датой, комментарием, необязательной ссылкой и временем регистрации. Прямой выбор соответствующего этапа открывает форму события. Отправка КП не создаёт фиктивную встречу. Завершённые действия нельзя записывать будущей датой. История не перезаписывается.

Статистика считает события только объектов с подтверждённым самостоятельным отбором, без архивных. Фильтр периода событий использует часовой пояс Asia/Yekaterinburg. Воронка показывает текущие этапы объектов в работе, а не сумму исторических переходов. Статистика не добавляется к существующим KPI из рабочих Google Sheets. Изменение источника на лид/мероприятие/активного клиента исключает объект из этой отдельной статистики.

## Хранение и доступ

Общая база Neon Postgres подключена через Vercel Marketplace на плане Free. Используется `DATABASE_URL`, либо отдельная `OUTREACH_DATABASE_URL`. Закрытая таблица `outreach_workspace` создаётся идемпотентно. В первой версии записи и история хранятся в JSONB с атомарным compare-and-swap по ревизии workspace и проверкой версии карточки. При конкурентном изменении разных ЖК операция повторяется; при изменении одной карточки пользователь получает сообщение о конфликте. Историю и каталог можно позже разнести по отдельным SQL-таблицам без изменения UI, заменив repository.

Все Server Actions проверяют сессию и валидируют входные данные Zod. SQL использует параметризованные запросы. Сохранение в production без общей базы отключается, временное серверное хранилище не используется. Для локальной разработки без базы предусмотрен файл `.data/outreach.json`, исключённый из Git, с атомарной записью и блокировкой.

Авторизация остаётся общей. В истории фиксируется имя общего входа, а не личность менеджера, который физически внёс изменение. Ответственный за ЖК — отдельное поле. Двухфакторная защита Vercel не относится к пользовательскому интерфейсу приложения.

## Будущее расширение

Для активных клиентов потребуется согласованный справочник клиентов, сопоставление с застройщиками/ГК и отметки используемых продуктов по ЖК. Текущий раздел не определяет активного клиента по названию группы автоматически и не считает отправленное КП внедрением продукта.
